# Metadata Editor product contract

This standalone static application edits XMP in JPEG, PNG and WebP. Vietnamese is the root, English is /en/, with both themes and the owner-approved shared VINASIG chrome. It processes one local file in memory at a time, up to 100 MiB. It never uploads, persists, executes or retrieves input content.

The initial form preserves all fields. Each of 11 XMP properties has Keep original, Set value and Remove field actions. Input selects Set value. The complete edited property is replaced, including qualifiers and language alternatives. Remaining XMP properties retain their XML semantics. EXIF and IPTC remain byte-preserved by default and their corresponding fields are not synchronized. Date values are entered explicitly as XMP dates, not generated or converted to local time. Author lists are ordered and keywords unordered, with one value per line. A blank Set value is an error. Use Remove field instead.

Users may remove the whole XMP packet or supported metadata outside XMP. These two scopes are labeled explicitly. Necessary display orientation, color profiles, alpha, animation and decoder data remain protected. ICC profiles can still contain descriptive information. The separate Cleaner is linked for privacy cleanup. Every operation is based on the original file, and restoring edits resets the form and XML to that original. Any input or option change invalidates the old download. Original and processed inspector views and JSON exports remain distinct.

The advanced XML action applies only the entered XML plus the outside-XMP removal choice, not the form fields. It rejects DTD/entity declarations, malformed XML, forbidden XML characters, nested/duplicate RDF roots, unsupported root shapes, more than 10000 elements, depth beyond 32, and packets above 1 MiB. It rejects changes to XMP orientation/color hints. A whole-XMP deletion containing those display hints is rejected conservatively.

Single standard XMP packets are supported. PNG compressed iTXt/zTXt is decompressed with an enforced 1 MiB bound and rewritten as standard uncompressed UTF-8 iTXt. JPEG standard APP1 data must fit its 65533-byte payload. Extended XMP and multiple packets are rejected, with no silent choice of one packet. HDR gain maps, JPEG JUMBF/multiple-image layouts and unknown critical or unsupported animated frame chunks retain the shared parser's fail-safe refusal.

Changing metadata removes existing PNG caBX or WebP C2PA manifest blocks. Unchanged form output is identical to the original file and leaves its provenance untouched. The editor never issues a signature, certifies origin or treats a parsed certificate as trusted. Remaining XMP provenance references and recorded history are unverified metadata. Raw XML may retain user-entered assertions, but these are not verification badges.

Outputs reread the complete container and XMP, compare every compressed image payload byte for byte and require identical dimensions. Required display information stays in copied original blocks or the shared display-only EXIF reconstruction when outside metadata is removed. The browser shows reread metadata, a safe decoded preview and matching payload SHA-256 values. Production never uses canvas to encode output. Pixel comparisons use canvas only in verification.

Workers terminate after 20 seconds and on replacement/reset/navigation. Stale worker callbacks are ignored by revision. Object URLs are revoked on replacement/reset. Image previews are bounded to 40 million declared pixels. Metadata rendering uses textContent and the shared bounded grouped inspector. No file contents are persisted, and only explicit actions download the edited image, XMP or JSON.

The control inventory includes file triggers, buttons, text/search inputs, textareas, checkbox/radio groups and disclosures. Select, calendars, color, range, progress and meter are NOT_APPLICABLE. The reviewed shared control surfaces retain native semantics, keyboard/touch behavior, resize handles, search clear, disclosure indicators and styled scrollbars. Script-unavailable file selection stays disabled. Chromium, Firefox and WebKit are required. Physical phones and screen-reader certification are separate from automated coverage.

The three metadata tools share the same ordered Reader, Cleaner and Editor navigation cards, with a decorative Lucide icon, purpose, localized destination and non-link current-page state. The shared identity header and footer remain byte-preserved. Reports render up to 25 fields per page with native first, previous, next and last buttons above and below the results. Searching includes all parsed fields and raw values, group changes and replacement files reset pagination, and explicit JSON exports include the complete parsed report independently of the active page or search. Sparse reports need no pagination controls. Empty search results have a distinct message.

The editor places its responsive two-column XMP form and full-width inspector in consecutive sections. Native anchor links let users jump between editing and inspection. Metadata length never stretches a parallel form column. Field labels and values share a proportional report grid and stack at the narrow breakpoint.
